# TSK-H5-013 — Defectos y correcciones del candidato local

Base publicada: `b8f4fc9db033de54bcdc01c5f7554647d02f11aa`. Solo sintéticos/loopback. Este registro no acepta ni publica H5-013. Las evidencias anteriores permanecen intactas; los fallos de desarrollo se conservan comprimidos sin normalizar sus bytes.

| ID | Causa y corrección | Comprobación correspondiente |
|---|---|---|
| F01 | El trigger nuevo se ejecutaba con owner sujeto a FORCE RLS sin política de lectura, ocultando su raíz. Su propietario pasa al executor existente, con políticas existentes; sin BYPASSRLS ni permisos directos al runtime. | V-MIG, creación real de suplido/economía, ACL y advisors. |
| F02 | Variables PL/pgSQL `v`/`svc` colisionaban con aliases SQL. Eliminación de variable no utilizada y alias inequívoco. | Apertura/evaluación de las tres dimensiones. |
| F03 | `tests/**/*.ts` incluía copias incompletas de código archivadas como evidencias H5-012. Exclusión de `tests/fixtures` como raíz de compilación; no se modifica ningún original. Los tests reales de `tests/` y sus imports siguen comprobándose. | Typecheck/build. Fallo original en `type-original.log.gz`. |
| F04 | La primera implementación de aplicabilidad podía aceptar ausencia declarada de documentación externa o economía propia. La necesidad se determina desde servicios canónicos y economía propia registrada; la declaración no puede dispensarla. Tararí interno no se transforma en proveedor externo. | Falta de factura/definición/costes, rechazo No aplica y positivo interno con cobro real acreditado de 2.100,00 EUR. |
| F05 | Riesgo detectado en revisión: snapshots económicos, Refund o fianza podían parecer suficientes tras cambiar su fundamento. Se contrastan revisiones/tokens actuales; cada lectura distingue estado histórico, estado vigente y aplicabilidad. Una necesidad documental nueva sin clasificación invalida la aplicabilidad hasta su revisión. No se persiste reapertura ni condición conjunta H5-015. | Documento actualizado, modificación posterior, factura corregida, restitución parcial y hash vigente. |
| F06 | JSON null podía atravesar comprobaciones SQL `NOT IN` por lógica ternaria. Se exige un valor definido para acción, dimensión y conclusión. | Negativos con códigos de rechazo exactos; cero evaluación creada. |
| F07 | Primer build de la copia aislada falló porque Turbopack rechaza node_modules enlazado fuera de su raíz. Corrección exclusivamente del entorno de ensayo mediante dependencias físicas de una instalación frozen. | Nuevo build sobre el mismo producto; FAIL original conservado. |
| F08 | La nueva fixture podía incluir un evidenceId anterior al construir el hash de una prueba, haciendo inespecífico el rechazo negativo. Se excluyen operationId/evidenceId y se exige el código de criterio exacto. El ensayo de inhabilitación usa su propia base y sesión nueva tras reactivar el actor, porque la sesión anterior queda revocada legítimamente. | Focal estricta final; los verificadores históricos no se modifican. |

Las correcciones F01/F02/F04/F05/F06 afectan exclusivamente código nuevo de H5-013. F03 modifica solo configuración de compilación. F07 es del entorno de ensayo. F08 afecta únicamente verificadores nuevos de H5-013. No se cambian reglas APPROVED, expected anteriores, guardas históricas ni evidencias originales.

Los estados definitivos y recibos de verificación figuran en [evidence-TSK-H5-013.md](evidence-TSK-H5-013.md). F01–F08 quedan CLOSED en el alcance técnico local tras la focal estricta28/28, regresión2628/2628 y gates documentados. F04/F05/F06/F08 incluyen hallazgos estáticos de revisión, sin inventar un FAIL ejecutado anterior. La primera ampliación del ensayo de factura falló correctamente por la incidencia de pago sin aprobación previa; se corrigió la fixture para autorizar antes de registrar el hecho. H5-013 sigue pendiente de aceptación y publicación.
